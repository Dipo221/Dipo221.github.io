這支只放**還欠的**。做完就整條搬去 `CHANGELOG.md`，不要打勾留在原地——
打勾的清單只會越長越難掃，而且做完的事情該留下的是推理，不是一個核取方塊。

三份文件的分工：

| | |

## 先過這一關

新想法進來之前先問一句：

> **這個功能會不會讓「三天沒開」變成一件有罪惡感的事？**

會的話就不做，不管它多好玩。沒有飢餓值、沒有清潔度、沒有心情條、
沒有連續登入獎勵、沒有任何會因為你沒來而變差的數字。bond 只增不減，
`test.html` 有一條測試守著 `bondDelta >= 0`。

這條是地基不是規矩，完整的理由寫在 `world.js:8-13`：這個遊戲存在的意義
是忙完之後喘一口氣，不是再給一個 deadline。養成遊戲的本能反射會一直想加
這種東西回來，所以這段放在最前面，不是最後面。

**注意這條擋的是「因為你沒來所以變差」，不是「壞事」。**

Disi 今天沒抓到小動物很懊惱——那可以有，而且它根本不在這條規則的管轄範圍內。
明陽的說法是準的：**牠只對「沒抓到」這件事懊惱，懊惱一下就過了，跟你沒有關聯。
那就只是一條敘事詞。**

所以真正的判準有兩層，先問第一層：

1. **這東西裡面有沒有玩家？** 沒有的話它是敘事，不是狀態，直接放行。
   敘事詞的特徵是：沒有數值、不影響任何事、也修不好。牠的壞心情你插不了手，
   就像你也管不到牠昨天在想什麼。
2. **真的牽扯到玩家的東西，才問**：這件事會不會因為你來了就變好？
   會的話它就是在要求你出席，那就是衰減換了個樣子。

這兩層的實作差別很大：敘事詞是「日期 → 字串」的純函式，不進存檔、不被任何
邏輯讀取；狀態則要存、要讀、要有人維護。**能寫成敘事的就不要寫成狀態。**

## A · 房間變成 8-bit（剩下的四項）

### 4. 貓在房間裡自由走動 — 小（本來是中，兩輪房間各順手做掉一半）

**已經做掉的部分**：`cat.y` / `cat.targetY` 存在了，`step()` 的位移是兩軸的
（`script.js` 的 `step()`，縱向速度是橫向的一半——正面走看起來本來就比較慢），
`goThenDo()` 收 `(x, y)`，鏡頭會跟著貓橫向捲（`script.js` 的 `follow()`）。

**為什麼會提早做**：滿版房間在手機上一次只看得到 44%，貓走出去畫面就空了，
所以鏡頭非做不可；而 `approach`（走到你面前）本來就是往畫面前方走，
沒有 y 軸做不出來。機制既然一定要存在，就一次做完，沒有只做半套的省法。

**可走範圍那條也做掉了**（原第 14 項的 M1 順手，已搬去 `CHANGELOG.md`）：`FLOOR` 現在讀
`room-data.js` 的 `floorTop` / `floorBottom`，而那支是 `pixel.py` 從
`art/room.py` 的 `walk_rows` 產的。改房間佈局不用再回頭改 JS。

**剩下的只有一條**：

1. **貓不會被東西擋住也不會被東西遮住。** 牠可以直接走過桌子，
   而且永遠畫在所有東西前面（`.cat` 的 `z-index: 2`）。
   走到桌子後面應該要被桌子蓋掉——那需要把家具從背景圖拆成獨立的一層，
   再按 `cat.y` 排前後。這件事跟第 5 項（東西要能點）拆的是同一層，
   所以**排在 5 後面做，不要自己先拆一次**。

**近大遠小還是不做**——貓縮放會糊掉（24×24 也一樣，非整數倍就是會糊），
而且那是 3D 的解法不是 8-bit 的解法。縱深靠遮擋表現，不靠大小。

### 6. 窗外的天氣 — 中

**做什麼**：窗外除了跟著台北時間亮暗，也跟著**淡水真實的天氣**變。

**為什麼**：時間讓房間會呼吸，天氣讓它是**今天**。外面在下雨的時候
開著這一頁，窗外也在下雨——那一下就不是在看一張圖了。

**天氣要用淡水的，不是看的人所在地的。** 跟時區同一個道理：
Disi 住在淡水的房間，牠窗外下不下雨跟你在哪裡看沒有關係。
座標寫死 25.18, 121.44。

**API 選 Open-Meteo（`api.open-meteo.com`），因為它不用金鑰。**
這是硬條件不是偏好：這是純靜態站，任何金鑰都會直接寫在原始碼裡被看光。
中央氣象署的資料更權威，但要申請授權碼，公開 repo 放不了。
Open-Meteo 免費、無金鑰，回 WMO 天氣代碼，
對應成晴／陰／雨／雷雨／霧幾種就夠了。

**已經先探過真的端點**（2026-08-27），免得做到一半才發現不能用：

```
https://api.open-meteo.com/v1/forecast
  ?latitude=25.18&longitude=121.44
  &current=weather_code,is_day&timezone=Asia/Taipei
```

回 200、無金鑰、帶 `Origin` 時回 `Access-Control-Allow-Origin: *`，
所以純靜態站打得到。`current.weather_code` 是 WMO 代碼、`is_day` 是 0/1。
順帶一提牠回的座標會吸附到最近的網格點（25.13, 121.46），對淡水來說夠近。

**那一層 2026-08-28 已經拆好了**，這一項不用再動架構，只要往上加圖。

當初拆是為了修黃昏那扇灰窗（原因與經過見 `CHANGELOG.md`），但拆出來的東西
就是這一項要的：`.room-sky` 是四張整張房間大小、只有玻璃不透明的疊圖，
z-index 5，**疊在兩層時段層上面所以不吃 multiply**。天空色的單一事實來源是
`art/room.py` 的 `SKY_TOD`，`pixel.py` 照它算出 `art/room-sky-<時段>.png`。

**所以天氣要畫在哪裡**：再開一層跟 `.room-sky` **同構的兄弟層**
（`.room-weather`，z-index 6），一樣是整張房間大小、只有玻璃不透明。
雨絲、霧、雲照樣進 `room.py` 當資料算出來，不要手畫，也不要用 CSS 動畫
——房間裡的東西都是像素的，一條平滑的雨線會跟旁邊的硬邊打架
（那正是第 12 項在講的問題）。

分成兩層而不是把天氣揉進 `SKY_TOD`，是因為它們的維度不一樣：
時段有 4 種、天氣有 5 種，揉在一起要畫 20 張圖，分開只要 4 + 5 張。
晴天就是「沒有天氣層」，不用畫。

**動到哪**：`script.js` 加抓天氣那段、`style.css` 加 `.room-weather`
（照 `.room-sky` 那幾行複製，`?v=` 的規矩一樣）、`room.py` / `pixel.py` 加圖、
`world.js` 加「WMO 代碼 → 房間狀態」的純函式（那支不碰 DOM，所以測得到）。

（**注意**：`room.py` 的 `EMISSIVE` 存的是夜晚的顏色不是白天的。
窗已經有自己的一層了，但 `EMISSIVE` 還留著給兩盞燈用，
不要順手把它改成天空色——那會讓半夜的窗變成一片大白天。）

**兩條規矩，跟 Abacus 那次同一套**：

- **服務掛掉不能影響遊戲。** 抓不到天氣就退回只看時間的房間，貓照常跑。
  整頁離線也要能玩，這本來就是它的優點。
- **要快取。** 每次開頁都打一次 API 是浪費也不禮貌。
  存 localStorage 快取 30 分鐘左右——天氣本來就不會分鐘級地變。

### 12. 那道光不是像素的 — 小

**做什麼**：`.room-beam`（從窗戶斜下來那道光，`style.css` 的 `.room-beam`）
是 CSS 的 `clip-path` 多邊形，邊緣是平滑的斜線。整個房間、貓、家具全都是
硬邊的方格，只有它是。放大看很明顯。

**為什麼還沒做**：不確定該不該修。**平滑的光反而比較像光**，
真的 8-bit 遊戲裡的光柱是有階梯狀鋸齒的，但那是當年硬體逼出來的限制，
不是好看。這是明陽的眼睛要判斷的事，不是我該自己決定的。

**原第 14 項的 M1 一度以為會順手做掉它，結果沒有。** 那一版只把座標換算成
新的 20×11 格，斜邊還是平滑的。記在這裡是因為 M1 的計畫書裡寫了會關掉，
別下次翻計畫書就以為它已經沒了。

**但 M1 讓它變便宜了**：現在有一層 `room-light.png`（`mix-blend-mode: screen`
的發光層，`pixel.py` 從磚號表產）。光柱畫進那張圖就自動是像素的，
而且會跟著窗一起亮暗，不用自己維護一套 `--room-beam` 色。
要做的話走這條，不要再去改 `clip-path` 的座標。

### 13. 橫向捲軸被藏起來了 — 小

**做什麼**：`.room-bleed` 設了 `scrollbar-width: none`（`style.css:119`）
和 `::-webkit-scrollbar { display: none }`，所以手機上房間可以左右滑，
但**沒有任何東西告訴你可以滑**，也沒有捲軸可以拖。

**為什麼會這樣**：一條系統捲軸橫在像素房間下面很醜，而且桌機根本不會出現
（桌機是整間都看得到的）。所以現在只有手機受影響。

**為什麼還是要處理**：看不到的捲軸對兩種人是壞的——用捲軸拖的人沒得拖，
用鍵盤的人不知道那塊可以聚焦。目前鏡頭會自動跟著貓跑（`script.js:516`），
所以不至於永遠看不到貓，但那是「系統幫你決定看哪裡」，不是「你可以自己看」。

**可能的做法**（都還沒挑）：房間左右邊緣加漸層陰影暗示還有東西、
第一次進來浮一句提示（正好接第 7 項）、或者乾脆把捲軸做成像素風的自訂樣式。

## B · 氣氛

### 7. 提示文字改成浮出又消失 — 小（**現在多背一件事：告訴人可以點**）

**做什麼**：`.hud-note` 從常駐一行，改成浮出來、停幾秒、淡掉。

**為什麼**：現在那行永遠佔著位置，沒事的時候是空的，有事的時候突然長出字。
它常駐就變成 UI 的一部分；浮出來的東西才像是「剛剛發生了什麼」。

**這一項現在還欠一個第 5 項留下來的洞。** 三顆按鈕刪掉了（2026-09-03），
而**按鈕會自我介紹、房間裡的東西不會**——第一次進來的人不知道貓可以摸、
碗可以點。游標變手不夠（手機沒有游標）。所以這一項要多做一件事：
**第一次進來浮一句話出來**，例如「摸摸看牠」。這是目前唯一的發現途徑，
在它做完以前，新訪客很可能什麼都不會點。

**動到哪**：`style.css` 的 `.hud-note`、`script.js` 的 `showNote()`。

**三件不能忘的**：

1. **`aria-live="polite"` 要留著。** 現在在 `#note` 上，而且**它是全頁唯一
   一個**——桌機的介面條被剝光只剩這一行字，就是為了留住它。
   改成浮動元素很容易連它一起弄丟。
2. **`prefers-reduced-motion` 要處理。** 開了減少動態的人一樣要看到字，
   只是不要飄——淡入淡出留著、位移拿掉。這頁已經有一整套動態處理，照那個做。
3. **手機那條有長度上限。** 22px 的中文一行約 15 個字，現在留了兩行的高度。
   改成浮動的之後如果脫離那個框，記得長句子還是會需要換行。

### 8. Disi 自己的一天 — 中

**做什麼**：兩件事，合成一項，因為它們是同一個東西。

- **每日心情**：點貓的時候，除了摸摸，還會講今天過得怎樣。
  「Disi 今天曬了太陽，覺得很舒服。」「Disi 今天沒抓到那隻小動物，有點懊惱。」
  「Disi 今天出去帶了東西回來，很得意。」
- **偶爾不在家**：進來的時候房間是空的，提示寫「Disi 跑出去玩了，過段時間回來看吧」。

**為什麼是同一項**：「今天出去帶了禮物回來」這句心情，講的就是牠出去那件事。
分兩個功能做，會變成兩套各自隨機、互相矛盾的敘述——
牠明明在家，卻說今天出去玩過。同一個「今天」只能有一份。

**這是整份清單裡最能打中核心的一項。** 這個遊戲賣的是「有一隻貓住在那裡」，
而住在那裡的東西會有自己的一天，包含不順的那種，也包含你不在場的那部分。
牠會自己出門，是這件事最強的證據——牠的生活不是繞著你轉的。

**動到哪**：`world.js` 全部（新的純函式：今天的心情、現在在不在家）、
`script.js` 接上去、`test.html` 補測試。**不用碰美術**，所以跟軌道 A 完全獨立。

**四條設計限制，每一條都對應一個會壞掉的地方**：

1. **同一個台北日，所有人看到同一份心情，重整不會重骰。**
   用 `World.rng()` 配 `taipeiDate()` 當種子——跟禮物同一招
   （`world.js:26-43`）。這是世界層的東西，不是各自存檔裡的。
2. **心情是敘事，不是狀態。** 這條有具體的實作意義，不只是說法：
   心情**不進存檔、不被任何邏輯讀取、不影響 bond 也不影響行為**，
   就是一個「台北日期 → 字串」的純函式。牠懊惱一下就過了，你插不了手。
   一旦有人想讓「摸摸可以讓牠心情變好」，它就從敘事變成狀態，
   然後就變成一個要你出席的任務了。
3. **出門要有回來的時間，而且要講出來。** 「過段時間回來看吧」後面要能接
   大概多久（「大概半小時」）。沒有歸期的空房間是被放鴿子，
   有歸期的是牠出門了——差別全在這裡。
4. **出門要短、要少、要挑時間。** 一天最多一次，一次幾十分鐘，
   而且只在牠活力高的時段（黃昏 17-19 那個高峰，`world.js:128`）——
   下午兩點 energy 0.12，那個時段牠應該睡死在家裡。
   **絕對不能常常撲空**：訪客進來看到空房間，那可能就是他對這個遊戲的全部印象。

### 9. 背景音樂／環境音 — 中

**做什麼**：可以開的背景聲音，一顆按鈕開關。掛在副螢幕的時候有人陪。

**為什麼**：這是明陽對這個東西真正的用法——不是玩，是開著。
有聲音才真的像隔壁房間有一隻貓。

**版權是這一項的主要限制，跟當初挑素材包同一件事**
（`art/LICENSE.txt` 那整段比較）：**repo 是公開的，把音檔 commit 進來就是散布**，
所以授權必須明確允許散布，不能只是「可以用在你的專案裡」。

**建議的順序**：

1. **先做程式合成的環境音**——Web Audio 生白噪音／棕噪音，
   加一個低通濾波器就是雨聲或風聲的底。**零檔案、零授權、零下載量。**
   而且這跟這個 repo 的作風一致：貓是算出來的不是下載的，聲音也可以。
   **等第 6 項做完，聲音可以跟著窗外的天氣走**——外面下雨，聲音就是雨。
2. **melody 之後再說。** 真的要 lo-fi 的旋律就得找 CC0 或 CC BY 且明講可散布的
   曲子（Pixabay、Free Music Archive、Incompetech 都要一首一首確認），
   或者用 Web Audio 自己合成。先不擋，但不要為了它卡住整項。

**動到哪**：新的 `audio.js`（跟其他幾支一樣不碰 DOM，才測得到）、
`script.js` 接按鈕、`index.html` 加開關、`style.css`。

**四條規矩**：

1. **預設關，而且要記住選擇。** 存 localStorage（`cat-room:audio`，
   照 `<範圍>:<功能>` 慣例）。
2. **絕對不自動播放。** 瀏覽器本來就會擋，而且沒預期的聲音是很失禮的事。
   那顆按鈕正好就是 Web Audio 需要的那個使用者手勢。
3. **切到別的分頁要停或轉小。** 找不到聲音是從哪個分頁來的，很煩。
4. **音量要低，而且可調。** 這是背景，不是內容。

## 之前就想做、還沒排進路線的

### 10. 訪客貓 — 大

**做什麼**：別的貓偶爾路過窗外，或走進房間，Disi 有反應。

**為什麼**：第一輪選型時就講好「A 起手（一隻貓一個房間），之後加 B（訪客貓）」，
架構是照這個留的空間。目前完全沒有實作。

**動到哪**：幾乎全部。`cat.js` 的狀態機要能同時跑兩隻、`world.js` 要決定
誰什麼時候來（必須是時間的純函數，不然每個人看到的訪客都不一樣）、
`disi.py` 要畫第二隻貓、`script.js` 要多一個 sprite 元素。

**先想清楚再動**：訪客貓不能變成「你沒來就錯過了」。錯過感是衰減的變形，
一樣過不了最前面那一關。第 8 項的四條限制在這裡也適用。

### 16. 8-bit 的漢堡選單 — 中（**畫好了但是死的，優先度因此升高**）

**做什麼**：一顆漢堡按鈕，點開是選單。「回首頁」放進去，以後的功能也放進去。

**現況：那三條線已經在手機的介面條左上角了，但它點下去沒有反應。**
明陽 2026-09-03 同意先擺位置不接功能。它現在是 `div` 加 `aria-hidden`，
不是 `<button>`——所以鍵盤和螢幕閱讀器碰不到它（那是刻意的，一顆會被唸成
「按鈕」卻沒反應的東西比沒有還糟），但**看得到的人會去點，然後什麼都沒發生**。

**這是這一輪唯一留下來的已知缺陷**，接上去的時候要把那個 `div` 換成真的
`<button>`，並拿掉 `aria-hidden`。

**為什麼**：明陽 2026-09-02 提的。滿版之後版面要保持乾淨，但功能只會越來越多——
需要一個「東西可以放進去」的地方，否則每加一個功能就要在畫面上長一顆按鈕出來，
滿版做完馬上又被啃掉。

**它要是 8-bit 的，所以要額外畫。** 這是明陽指定的，不是我猜的。
展開的面板、選項的邊框都不能用瀏覽器預設的樣子——
整頁只剩房間的時候，任何一個現代感的 UI 元件都會比之前更刺眼。

**畫法照介面條那一套**：CSS 畫的木牌（頂面最亮 A、次亮 W、正面 w、
底下側面 j、四周 o 描邊），字用 Cubic 11 且只能是 11 的整數倍。
顏色用 `style.css` 已經有的 `--w-*` 變數，**不要再抄一份十六進位**
——`pixel.py` 的 `lint_hud_palette()` 只認得登記過的那幾個。

**動到哪**：`index.html` 把那個 div 換成按鈕、加面板；`style.css` 新的一段；
`script.js` 開關的邏輯。**不用碰 `art/`**，介面條證明了這類東西 CSS 畫得出來。

**桌機還沒有漢堡。** 桌機的 `.hud-row` 是 `display: none`，所以那三條線
只有手機看得到；桌機的「回首頁」還在頁尾。接這一項的時候要一起決定
桌機的入口要不要浮在房間上。

**先問清楚再畫**：選單裡除了「回首頁」和「減少動態」還要放什麼？
現在只有兩項，做一個選單裝兩項是划不來的——**這一項的價值取決於第三項是什麼**。

**無障礙不能因為它是像素風就打折**：真的 `<button>`、`aria-expanded`、
Esc 關閉、開啟時焦點進面板、關閉時焦點回按鈕。

### 11. 累計被摸總數，跟今天的並排 — 小

**做什麼**：`.meta` 那行變成「今天被摸 3 次　·　總共 128 次」。

**為什麼**：今天的數字是給「牠今天過得怎樣」看的，累計是給「牠住了這麼久」
看的，兩個講的不是同一件事。生活天數已經在小標上了，累計摸摸跟它是一對。

**動到哪**：`script.js` 的 Abacus 那一段。今天的數字是一天一把 key
（`cat-room-touch-YYYY-MM-DD`），累計要另外開一把不重置的。

**有一塊髒資料**：舊的 `cat-room-pets` 那把 key 裡有 7 次是開發時驗證點出來的，
Abacus 只能加、不能減也不能刪。所以要嘛用一把全新的 key 從 0 開始
（那就永遠少掉真實的前幾天）、要嘛接受那 7 次。我傾向開新的：
這個數字的意義是「有人來看過牠」，混進測試點擊就不是那個意思了。

## 刻意不做

這段的用處是**不要再分析第二次**。理由都推過了，寫在這裡是為了下次想到
同一個點子的時候，先看到「已經想過了，結論是不做」。

- **逐格精確同步**（所有人看到一模一樣的畫面）。要把時間切片、在切片內重播
  狀態機才做得到。而台北時區已經拿到九成效果——下午兩點 energy 是 0.12，
  進來的人幾乎一定看到一隻在睡的貓；黃昏進來一定看到牠在動。
  完整理由在 `world.js:173-176`。

- **關係層跨裝置同步**（筆電和手機共用一份 bond 和禮物）。要有後端存 `lastSeen`。
  Abacus 只能加、存不了時間戳；GitHub API 每次來訪都 commit 會洗爆版本紀錄，
  而且有 30 秒延遲。真的想要就得另外找後端，那是另一個決定。

- **把 private 層改成全站共用**。這個看起來像是「同步」的簡單版，其實會壞掉：
  `lastSeen` 一旦全域共用，只要站上有人來過就會被刷新，
  「你離開了五天」那一格永遠不會再觸發——路人會把我自己的離開時間用掉。

- **近大遠小**（貓走到後面變小）。像素圖縮放會糊掉（重畫成 24×24 之後也一樣，
  問題在非整數倍不在解析度），而且那是 3D 的解法，不是 8-bit 的解法。見第 4 項。

- **任何形式的衰減**。同最上面那一段。列在這裡是為了讓它出現在「不做」的
  清單上，看得見。
