# 房間裡的貓 — 改動紀錄

這支只記「哪一版改了什麼、為什麼這樣改」。功能怎麼玩、設計原則、怎麼跑測試
寫在根目錄的 `README.md`。

日期是台北時間，括號裡是 commit。每一版的完整推理都在 commit 訊息裡，
要看細節用 `git show <hash>`；美術的部分還有另一層記錄——走錯的版本留在
`art/disi.py` 的註解裡，就在要改的那幾行旁邊。

舊版的圖不需要保存。`disi.py` + `pixel.py` 是決定性的，checkout 任何一個
舊 commit 再跑一次 `python pixel.py`，就會產出那一版的素材與校對圖。

## 2026-08-27 22:58 — 房間變成一張像素圖 (`57f3166`)

房間本來是四個絕對定位的 CSS 方塊配漸層，貓是 16×16 的像素。兩種語言擺在
一起，貓看起來像貼在背景上，不是住在裡面。這一版把房間也變成資料算出來的
像素圖（TODO 第 3 項）。

**做法是磚組 + 磚號表，不是整張畫。** 新的 `art/room.py`：十幾塊 16×16 的磚
配一張 16×7 的字元表，分 `bg`（牆、地板，每格都要有）和 `obj`（桌子、地毯、
窗、碗，`.` 代表空）兩層。搬家具就是改那幾行字元。整張硬鋪要 28,672 個像素，
用「一格一個字元」寫不完；8-bit 主機當年也不是那樣做的。

**尺寸是算出來的，不是挑出來的。** 一開始問題被寫成「桌機要寬、手機要窄」，
看起來得二選一。明陽自己給的解法把它拆掉了：**手機可以左右滑，桌機不用滑。**
兩邊的貓因此可以一樣大——`貓的大小 = 可用高度 ÷ 列數`，跟欄數無關。
所以列數決定貓多大，欄數是自由的，選 16×7：桌機一次看完，手機一次看到約
35%，鏡頭跟著貓跑。

**地板佔 7 列裡的 4 列，第一眼會覺得太多。** 那是留給 TODO 第 4 項的——
砍成兩列比例會好看一點，但貓就只剩一條線可以走，等於把縱深先鎖死。

**日夜是一張底圖疊一層 multiply，不是四張圖。** 四張圖是四倍美術量，
而且改一塊磚要改四次。`.room::before` 那層只換一個 `--room-tint`。
四個色值是**從舊的 `--room-wall` 反推**出來的，所以牆的顏色跟改版前逐位元
相同；`pixel.py` 的 `build_room_tod()` 會把這件事驗一次，對不上就印 MISMATCH。
那層刻意疊在貓上面——環境光本來就該打到貓身上，貓不該是唯一不受光的東西。

**兩個量出來才發現的錯**：

- **貓被壓成 72×71，不是正方形。** 站台全域有 `* { box-sizing: border-box }`，
  於是 `aspect-ratio: 16/7` 是套在**邊框盒**上的，1px 的框把內容盒擠成
  1145.4×500（比例 2.291 而不是 2.2857）。`.room` 因此獨自改回
  `content-box`，旁邊留了註解說明為什麼要推翻全域規則。
- **`--chrome`（房間以外的頁面高度）本來是用加法估的，差了 36px。**
  桌機因此會捲動 36px，違反「桌機不用滑」這條前提。改成在瀏覽器裡量：
  桌機 434、手機實測 418。手機**故意只填 340**——手機本來就會捲，
  少算那 78px 的頁尾，換來貓大 11px。

**順手做掉的兩件事**（TODO 第 1 項與第 4 項的一半）：

- **餵食不再背對著碗。** `cat.facing` 以前只在移動中更新，從碗右邊走過來的
  那幾次會背對著碗低頭吃地板。現在抵達時先讀 `cat.faceAt` 轉向，才進 `eat`。
  上一版留在這裡的「已知未處理」可以撤掉了。
- **貓有 y 軸了，鏡頭會跟。** 這超出原本只做房間的範圍，但兩件都繞不開：
  滿版房間在手機上一次看不完，貓走出畫面就變成空房間；而 `approach`
  本來就是往畫面前方走，沒有 y 軸做不出來。縱向速度是橫向的一半，
  正面走看起來本來就比較慢。TODO 第 4 項因此剩下一半，那一項已經改寫。

**`justify-content` 是 `safe center` 不是 `center`。** 房間比視窗寬的時候，
一般的 `center` 會把左半邊推到捲不到的地方——那不是美觀問題，是永遠看不到。

已知未處理：那道從窗戶斜下來的光還是 CSS 的平滑斜邊，只有它不是像素的；
multiply 推不出比底色更亮更暖的顏色，所以黃昏的天空不會變橘，晨昏兩個時段
現在長得很像；手機的橫向捲軸被藏起來了，沒有東西告訴你可以滑。
三條都寫進 TODO（第 12、13 項與第 6 項底下）。

## 2026-08-26 21:59 — 真的坐姿與低頭吃 (`ea6bddb`)

sit 和 eat 原本是兩個誠實的妥協：sit 是 idle 第 0 格定住不動，eat 直接
alias 到 idle，貓站在碗邊對著空氣吃。兩個妥協的理由都是「這包素材沒有那個
姿勢」——上一版素材改成自己畫的之後，理由就不成立了。

- sprite sheet 從 3 欄 3 排變成 3 欄 5 排，sit 與 eat 各拿到一排
- **sit**：頭與尾巴沿用 idle，只換肩膀以下。坐姿要成立靠兩件事——背要從
  肩膀往後下斜到落地的屁股（不是站姿那種平的）、肚子底下 x5-x6 要從 y13
  挖空到底。那個凹口是坐與站在剪影上唯一的差別，填掉就變成「站著但腿被
  擦掉」的貓
- **eat**：頭與身體分成兩層，`_eat(dy)` 只移動頭，結構上不可能把身體也
  挪掉一格。屁股抬到 y6、比頭頂還高——高低差本身就是「低頭」唯一的訊號，
  頭跟屁股一樣高的版本會糊成一條橫的麵包
- 前腳擺在 x9-x10 而不是胸口正下方，因為最深那一格頭會蓋到 x8。腳一定要
  三排：兩格奶油色直向疊起來才是一條腿，只給一排會讀成一顆白點
- `pixel.py` 的格數改成從 `SHEET` 算，不再寫死 3x3
- `sprites.js` 的 sheet 網址加 `?v=2`。**rows 一變就一定要加號碼**，
  否則快取裡的舊圖配新 manifest，第 3、4 排會取到圖框外面變成空白
- 測試 181 → 183，新增的兩條擋「哪天有人為了省格子又把它們指回 idle」

已知未處理：貓的面向只在移動時更新，從碗右邊走過來餵食時會背對著碗低頭
吃地板，大約十幾次遇到一次。以前 eat 假裝成 idle 時看不出來。

## 2026-08-26 20:06 — 素材改成自己畫的 (`ae70146`)

換掉第三方素材包，貓從此可以隨便改隨便散布。

- 移除 `cat-16.png`（16 bit kitty，CC BY 4.0），改用自己畫的 `disi-16.png`
- 新增 `art/disi.py`（像素資料：一格一個字元的地圖 + 七色調色盤）與
  `art/pixel.py`（算成 PNG，另外吐校對圖、GIF、跑 lint）
- 工具會存在，是因為畫的人看不見自己畫的東西。重點不是產素材，是產一張
  放大 20 倍、加格線與座標尺的校對圖，才有辦法講「(5,5) 那格拿掉」
- lint 守三件事：相鄰兩幀的差異（照真實播放順序，含接回第一幀那段）、
  頭只能整塊平移不能變形、行長與色盤。每一條都對應一個真的犯過的錯
- walk 與 run 共用第 1 排的同三格畫面，只差播放順序。同步回彈當走路很假，
  當跑步剛好是騰空那一下——一組畫面兩種步態
- play 從 alias 到 walk 改成 alias 到 run。它在地上跑得比較快，共用 walk
  的幀速時步頻跟不上位移，腳等於在打滑
- 順便修掉一個既有錯位：站姿腳掌踩 y14、睡姿踩 y15，貓一躺下整隻會往下跳。
  現在所有姿勢都踩 y15

## 2026-08-26 03:19 — 貓叫 Disi，訪客與主人分層 (`c27d961`)

原本的設計等於每個訪客各自認養一隻分身。改成只有一隻貓，是我的，別人是
過來看牠。

- 三層刻意分開：`world`（牠在做什麼、住了幾天，大家看到的一樣）／
  `shared`（今天被摸過幾次，記給所有人、只顯示給我）／
  `private`（bond、禮物、離開多久的訊息）
- private 留在各自瀏覽器是關鍵。lastSeen 如果全域共用，只要有人來過就會
  被刷新，「你離開了五天」永遠不會再觸發，路人會用掉我自己的離開時間
- 時間改用台北時區，不跟著看的人的所在地。Disi 住在淡水的房間，牠幾點睡
  跟你在哪裡看沒有關係
- 每日摸摸次數改成「一天一把 key」而不是歸零，因為那個計數器只能加
- 測試 130 → 181。有一組原本是靠運氣過的——它建的是本機時間，只因為開發機
  在台北才碰巧等於台北時間

## 2026-08-25 06:30 — 建立這個工具 (`cecbf71`)

研究做累了可以打開來看的東西。房間的光跟著真實時間走，貓維持真貓的晨昏性
作息：下午睡死，黃昏開始不安分。

- **整個東西建立在一條規則上：什麼都不衰減。** 沒有飢餓值、沒有清潔度、
  沒有心情，bond 只增不減。離開會被獎勵而不是懲罰——五天後回來，貓會叼
  一個牠找到的東西走過來。有一條測試確保 bondDelta 永遠不會是負的
- 邏輯放在 `world.js` / `cat.js` / `save.js` / `sprites.js`，四支都不碰
  DOM，所以 `test.html` 可以直接驅動（130 條）。`script.js` 只負責接到頁面上
- sprite 藏在 `sprites.js` 的 manifest 後面，換素材不用碰遊戲邏輯——
  這個決定後來真的用上了（見 2026-08-26 那兩版）
- 當時用的是 16 bit kitty by Maze.Bit.Boutique（CC BY 4.0），
  唯一一包明確允許在公開 repo 散布的
